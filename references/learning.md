# 学习与更新指南 (Learning & Ingestion Workflow)

## 一、 收到书籍、网页或视觉样稿时的防伪核验

1. **核对原始出处、版本与完整度**：
   - 记录标题、作者/设计师/研究机构、发布日期、URL 或 ISBN/版次、获取日期；允许收录**可追溯到具体设计师、品牌或原始发布页的纯审美作品**（无投放数据时如实记录“作品观察，效果未公开 / `editorial_analysis`”）。
   - **书籍 PDF 复合核验（防误杀也防伪书）**：先读取封面、版权页、目录及前 15–25 页正文。若核实属于 `Bookey`、`Blinkist` 等剔除原书排版图例的纯文字商业书摘，拒绝入库；但若正版教材或扫描件出现章节 `Summary` 或局部缺图，**不凭单一特征一刀切拒收**，应先核对版本、出版社与可读章节再决定。
   - **已读范围与译本诚实登记**：只登记本轮实际打开并核验过的 `pdf_pages` 或网页段落；未读章节保持未登记状态，绝不凭印象补齐；若仅核阅中文译本而未对照英文原版，英文提炼须标明为转述。

---

## 二、 用“五把解剖刀”拆解视觉案例（分开写“原作怎么做”与“下次可以借什么”）

每拆解一则广告、详情页改版或 UX 报告，强制分离**原作客观事实**与**可迁移条件法则**，提炼以下 5 项结构化内容：

1. **卡点症状 (`when_stuck`)**：用中英双语和用户自然口语写出设计师或运营在什么具体痛点下需要搜到这张卡（如：“看不出这是什么 / 像模板 / 想让人再看一眼”）。
2. **原作客观画面观察 (`observations`)**：照实保留原作的颜色、比例、字体、帧数与实验样本数据，不篡改原著或作品本身。
3. **图字分工机制 (`copy_visual_synergy`)**：拆解画面与文字是如何配合的——画面承担了哪部分直觉证明？文字或标注补充了哪部分非视觉信息？
4. **可迁移视觉动作 (`reusable_move` / `rule`)**：写清**“这招解决什么问题、在什么条件下适用、什么时候应该换招”**，避免把单件作品里的具体做法写成放之四海而皆准的禁令；若引用投放数据基准（如点击率/停留率），保留原报告数字与样本出处，但只作**排查预警信号**而非直接归因到构图。
5. **素材前提、失效边界与证据**　明确所需素材和适用范围。分别登记来源核对、方案认可或项目采用、受众实测结果。

## 三、 外部视觉案例搜集与预拆解交付规范

当用户要求“找几组参考案例/链接”或按流派搜集外部作品时，**不得只丢图库链接或堆砌主观形容词**，每组案例必须同步输出以下 4 项结构化预拆解信息：
1. **可核验原始出处**：品牌官网、代理商发布页、Ads of the World、It's Nice That 等可追溯来源（不得以无出处图床代替原始来源）。
2. **客观画面量值**：具体机位高度/角度、留白占比、色块/网格结构、正斜体字阶与光影方向。
3. **图字分工与可迁移动作**：画面承担什么直觉证明、文字补充什么信息，以及对应哪个下游执行通道（如通道 2 矢量直出、通道 4 棚拍）。
4. **库内映射与去重检查**：明确说明该案例是**补全现有方法子分支**（如 `M-036` 增补跨品类容器嫁接）、**新增独立 `M-*` 方法**，还是需补齐商业字阶后才可激活 `library/styles/` 空白母版。

---

## 四、 入库与校验

1. 在所选库下准备 `cases/<case-id>.md` 和 `cases/en/<case-id>.md`。在补丁的 `cases` 列表登记两条路径。只改正文时，也把已有案例 ID 放入补丁，指纹才会更新到该卡。
2. 完成你本轮要求的复核后，执行 `python3 scripts/library.py apply-patch --file patch.json --check-files`。使用自定义库时，把 `--library <目录>` 放在子命令前。
3. 工具为本次提交的案例生成中英文文本指纹，核对引用和未改动的卡片。校验通过后，保留旧目录和变更前的指纹备份至 `history/`，再用完整文件替换。失败信息会指出具体记录或文件。
4. 用 `validate --check-files` 查看终版状态。Windows CRLF 与 Mac LF 均可校验，正文改字需随案例更新。

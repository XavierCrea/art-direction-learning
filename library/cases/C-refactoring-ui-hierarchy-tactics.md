# Refactoring UI 界面层级七法：用字重色阶代替字号膨胀、用色差留白代替密集边框

[中文案例索引](../README.md) · [English](en/C-refactoring-ui-hierarchy-tactics.md)

[返回视觉案例库](../README.md) · 界面重构战术指南与 Before/After 视觉对比

- **卡点症状 (`when_stuck`)**　页面或详情页卡片看起来像粗糙的模板：重要的字只会无脑调大字号、到处是密集的黑灰表格边框、彩色背景上的灰字灰蒙蒙看不清、免费小图标直接拉大显得极其笨重、页面上每个按钮都涂满了鲜艳颜色分不清主次。
- **适用载体**　着陆页（Landing Page）、B2B 店铺装修模块、产品详情页信息卡、参数对比表、数据看板。

## 原材料里看到什么 (`observations`)

- Adam Wathan 与 Steve Schoger 在 *7 Practical Tips for Cheating at Design* 及完整专著 *Refactoring UI (2018)*（PDF p.36–64, p.172–179, p.208–213, p.224–227, p.238–241）中通过严密的 Before/After 界面重构图，给出了不依赖美术天赋的物理排版与层级降噪法则：
  1. **用色阶与字重建立层级，而非只靠字号（Size isn't everything, PDF p.38–41）**：新手觉得文字重要就放大、次要就缩小，导致字号失控。正确做法是固定 **2 档字重**（常规 `400–500`、强调 `600–700`，正文 UI 严禁使用 `<400` 的极细字重，p.39）与 **3 级色阶**（深色主信息、中灰次要信息、浅灰辅助注脚，p.40–41）；遇到主元素不够突出时，优先**通过弱化周边竞争元素来突出主角（Emphasize by de-emphasizing, p.46–47）**。
  2. **彩色背景上严禁用灰色字或低透明白字（Don't use grey text on colored backgrounds, PDF p.42–45）**：白底上用灰字有效是因为降低了对比度，但在深蓝/彩色背景上放灰字或单纯降低白字透明度（`opacity`）会让画面显得发灰发脏，且当背景有图案/照片时会直接透底（p.43–44）。正确做法是**吸取背景同色相（Same Hue），手工调整饱和度（Saturation）与明度（Lightness）选出专用的浅色文字**（p.45）。
  3. **平衡粗重面积与对比度（Balance weight and contrast, PDF p.56–59）**：实心图标单位面积墨量远大于文字，和文字并排时会显得头重脚轻，必须**主动压低图标颜色对比度（改用柔和浅灰/浅色）**以实现视觉平衡（p.56–57）；反之，若 `1px` 分割线降对比度后显得太淡，可通过**加粗线宽（如改为 `2px+` 浅色线）**补回重量而不刺眼（p.58–59）。
  4. **阴影加垂直偏移并配顶边高光模拟顶光（Emulate a light source, PDF p.172–179）**：自然界光源从上方照下，凸起卡片/按钮顶部受光（加 `1px` 手选同色系浅色顶边）、底部背光（加向下垂直偏移的小暗影）。
  5. **少用边框（Use fewer borders, PDF p.238–241）**：密集的 `1px` 边框会让详情页和卡片显得拥挤琐碎。改用三种无边框分隔手段：① 微妙的盒子阴影（Box shadow，p.238–239）；② 相邻区块使用轻微不同的背景色差（Adjacent background colors，p.239–240）；③ 直接加大间距留白（Extra spacing，p.240–241）。
  6. **不要把 16–24px 小图标强行放大 3–4 倍（Everything has an intended size, PDF p.208–209）**：`16–24px` 绘制的矢量小图标直接放大到 `64px+` 会显得线条粗蠢、比例失调。若只有小图标，应**将其保持原尺寸，装进一个带柔和彩色底色的圆形/圆角矩形容器内**（p.209）。
  7. **用局部彩色强调边条破除沉闷（Add color with accent borders, PDF p.224–227）**：在卡片顶部（p.224）、导航激活项（p.225）、提示框左侧（p.225）、标题下方短横杠（p.226）或页面最顶端全局彩条（p.226）加上一条品牌色粗边条，低成本拉升设计感。
  8. **按钮设计按“重要性金字塔”而非纯语义涂色（Semantics are secondary, PDF p.60–64）**：一屏通常只有 1 个真正的主行动点（Primary Action，用高对比度实心背景色）、1–2 个次要行动点（Secondary，用描边 Outline 或低对比浅底色）、以及三级行动点（Tertiary，用纯文字链接样式，p.60–61）。即便“删除/重置”是负面语义，只要不是当前屏幕的主任务，就不应涂成最抢眼的大红实心按钮，而应在点击弹出二次确认弹窗（Confirmation Modal）时才将删除升格为实心红主按钮（p.62–63）。

## 图字如何分工 (`copy_visual_synergy`)

- **字重与色阶负责“视线先后顺序”**：让读者无需阅读全部文字，仅凭深色粗体就能在 1 秒内抓取核心结论与关键数值，浅色常规体自动退居二线充当解释。
- **留白与底色色差负责“逻辑归组”**：把属于同一卖点或同一型号的图文包裹在同一浅色底板内，省去喧宾夺主的网格线。

## 可迁移的视觉动作 (`reusable_move`)

1. **三阶文字降噪**：检查当前卡片/模块，将字号种类收敛到 2–3 种，把重点数据设为 `600–700` 字重 + 深炭黑（如 `#0F172A`），单位与说明文字设为 `400` 字重 + 中灰（如 `#64748B`）。
2. **砍掉 70% 的内部边框**：在卖点网格或参数卡片中，删掉生硬的实线框，改用 `#F8FAFC` 浅灰底板配 `#FFFFFF` 白色卡片 + `16px–24px` 间距。
3. **小图标加底色容器**：卖点区的 `24px` 图标外层套一个 `48×48px` 的浅品牌色圆角方块（如浅蓝底 `#EFF6FF` 配深蓝图标 `#2563EB`）。
4. **首屏/卡片按钮三级分化**：确保主询盘/购买按钮是唯一的高饱和度实心色块；“下载规格书 / 查看全部”退化为描边按钮或带箭头的文字链。

## 素材前提与迁移边界 (`asset_prerequisites` & `transfer_limits`)

- **素材前提**：需先明确每个模块里哪句话/哪个数字是第 1 优先级，哪个按钮是唯一主转化目标。
- **禁用边界**：正文字重绝不可低于 `400`；深色工业风背景（如 `#0B1120`）上的次要文字不可直接用纯中灰 `#888888`，应使用带蓝调的浅灰蓝（如 `#94A3B8`）或半透明白。
